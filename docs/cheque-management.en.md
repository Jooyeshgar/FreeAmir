# Cheque management

English | [فارسی](cheque-management.fa.md)

The cheque module manages notes receivable, notes payable, guarantee cheques, and company checkbooks.
All records are company scoped. Dates are stored as Gregorian dates and entered/displayed through the
application's Jalali helpers.

Direction, purpose, and lifecycle values are defined by the single integer-backed
`App\Enums\ChequeType` enum. The database stores them in regular `SMALLINT` columns—not database
`ENUM` columns. The enum's `directions()`, `purposes()`, and `statuses()` methods expose the valid
subset for each field.

## Lifecycle

- Receivable: `registered -> deposited -> cleared`, `registered -> endorsed`, or
  `deposited -> bounced -> deposited`. Registered/bounced cheques may be returned to the customer.
- Payable: `issued -> cleared`, `issued -> bounced`, or `issued/bounced -> cancelled`.
- Guarantee: `guarantee_received` or `guarantee_given` is off-balance until `execute` changes it into
  the corresponding settlement lifecycle.
- `revert` only reverses the latest active transition. It removes that transition's generated payment
  and accounting document while retaining the audit history as reverted.

Updates use a row lock and version number so two users cannot transition the same cheque concurrently.
Cheque master data can be edited until the first lifecycle action; the initial accounting document is
rebuilt transactionally. Deleting a cheque transactionally removes its linked payments, histories, and
all accounting documents generated by the cheque.

## Accounting entries

The transaction sign convention follows the rest of FreeAmir: negative values are debit and positive
values are credit.

| Event | Debit | Credit |
|---|---|---|
| Receive | Notes receivable `013001` | Customer |
| Deposit | Notes in collection `014001` | Notes receivable `013001` |
| Clear received | Bank account | Notes in collection `014001` |
| Endorse | Vendor | Notes receivable `013001` |
| Return received | Customer | Notes receivable `013001` |
| Issue | Vendor | Notes payable `020001` |
| Clear issued | Notes payable `020001` | Bank account |
| Bounce/cancel issued | Notes payable `020001` | Vendor |

Every posting is created and approved through `DocumentService`; clearance and endorsement also create
a cheque-method `Payment` linked through `payments.cheque_id`. Guarantee registration creates neither a
document nor a payment.

## Invoice settlement

Approved invoices can be settled from the invoice details page by registering a cheque. Sales and
return-purchase invoices create a received cheque; purchases and return-sales create an issued cheque.
The cheque registration/issuance document is also linked to the invoice's `Payment`, so invoice settlement
does not create a duplicate accounting document. Clearing the cheque later remains an independent lifecycle
posting. Unlinking the payment preserves the cheque and its document, while deleting the cheque removes the
payment and recalculates the invoice status.
